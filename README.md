# Etelä-Pohjanmaan hyvinvointialue – dashboard

React + TypeScript + Vite implementation of the "Etelä-Pohjanmaan hyvinvointialue" design canvas (six views).

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # typecheck + production build to dist/
```

## Views (routes)

| Route | View |
| --- | --- |
| `/` | Kunnat – the 18 municipalities, numbered by population |
| `/palvelupisteet` | Service points on the map, filter by type, click for details |
| `/vaesto` | Population & wellbeing summary with municipality tables |
| `/kuntakortit` | Municipality cards – pick one or many on the map, values combined |
| `/ennuste` | Population projection 2024–2045 scenario tool (slider, play, charts) |
| `/ajomatkat` | Drive times from each municipality to a chosen service point |
| `/hoito` | Care search: pick one of 20 example care needs and a municipality, get the nearest point offering it with drive time and distance (need → point-type mapping in `src/content/careNeeds.ts`, tested) |
| `/muutokset` | Service-network scenarios: close a service point or lighten it to a sote-piste and compare drive times to the nearest remaining service, per municipality and population-weighted (logic in `src/lib/scenario.ts`, tested) |

## Structure

- `src/styles.css` – design tokens (colours, fonts, radii) and shared classes
- `src/components/` – `RegionMap` (schematic SVG map + overlay positioning), `DataTable`, and UI primitives in `ui.tsx` (`PageHeader`, `StatTile`, `SectionTitle`, `Button`, `CompareBars`, `CategorySwatch`)
- `src/data/` – municipalities + map geometry, service points, and JSON datasets
- `scripts/extract-data.mjs` – one-off script that pulled the JSON datasets out of the design's `.dc.html` sources

Figures are as collected in the design (11/2026) and should be checked against the original sources before official use.

## Data: database and fetch pipeline

All project data lives in a SQLite database (`data/hyvaep.db`, created on first run; uses Node's built-in `node:sqlite`, no server). The app does not read the database directly: `export` writes the JSON files in `src/data/` that the app imports, so the site stays a static build.

```bash
npm run data:seed          # create the DB from the design baseline + curated files, then export
npm run data -- fetch all  # fetch from all external services (or name jobs: fetch population health)
npm run data -- export     # write src/data/*.json from the DB
npm run data:update        # fetch all → derive → export
npm run data:status        # row counts and recent runs
npm run data -- list       # jobs and their sources
npm test                   # pipeline tests (offline, external APIs faked)
```

| Job | Source | Data |
| --- | --- | --- |
| `population` | Tilastokeskus StatFin 11re | Population by age group (latest year) |
| `projection` | StatFin 14wx | Population projection 2024–2045 by age group |
| `employment` | StatFin 115x | Employment and unemployment rate, 18–64 |
| `education` | StatFin 12bq | 15+ population and tertiary degree holders (levels 5–8) |
| `income` | StatFin 14ww | Median income, low-income rates, basic security |
| `health` | THL Sotkanet | Indicators 5641, 5661, 5651, 5663, 306, 2345, 5, 191 |
| `geocode` | Nominatim | Coordinates of municipality centres and service points (only missing ones; `--force` to redo) |
| `drivetimes` | OSRM | Drive time / distance, every municipality centre → every service point |
| `derive` | – | County (HVA) totals = sum of 18 municipalities; population, age and tertiary shares |

**Schema** (`db/schema.sql`): `area` (municipalities with Tilastokeskus codes `KU005`…, county `HVA`, region `MK14`, country `SSS`), `indicator`, `observation` (indicator × area × period, with status `ok` / `suppressed` / `missing` / `derived`), `service_category`, `service_point`, `drive_time`, `fetch_run` (audit log of every job) and `raw_response` (every API response, for debugging and re-parsing).

**Curated data**: the service-point network has no API (hyvaep.fi). Edit `db/seeds/service-points.json` (names, categories, addresses, notes, Nominatim query, optional fixed `lat`/`lon`) and run `npm run data -- seed`.

**Design baseline**: `db/seeds/design-baseline/` holds the values collected for the design (11/2026). `seed` loads them so the DB is complete without network access; fetched values overwrite them. The tables on the "Väestö ja hyvinvointi" page (`vaestotiedot-tables.json`) contain editorial notes and are not generated by `export`.

**Card periods**: the years shown on the municipality cards are set in `pipeline/cards.ts` (`CARD_SPEC`). After fetching a newer statistical year, update the period and title there.

**Usage policies**: requests are throttled per host (Nominatim ≤ 1/s), retried on 429/5xx, and identified with `HYVAEP_USER_AGENT`. For regular or production use, run your own OSRM and set `NOMINATIM_EMAIL` (see `.env.example`).
